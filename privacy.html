Personal Google Drive Sync

Privacy policy

Effective date: October 11, 2026

Scope

This policy describes the owner's privately configured Google OAuth application, displayed as “rclone,” used with the rclone command-line program for personal Google Drive synchronization. This is not a public multi-user service or the official rclone project's shared OAuth application.

Information accessed

When the owner authorizes an account, the local application can access Google Drive files and folders, their contents, and metadata needed for synchronization, such as names, identifiers, sizes, and modification times. It may use basic account information to identify the authorized account.

The configured Drive permission permits reading, creating, updating, moving, and deleting files. OAuth access and refresh tokens are used locally to authenticate requests to Google's APIs.

How information is used

Drive information is used to perform the owner's requested file synchronization, compare changes, and maintain operational state and diagnostic logs. This synchronization application does not use Google API data for advertising, sale, or training AI models.

The application's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements.

Storage and sharing

Files are transferred between Google Drive and the owner's computer using Google's APIs over HTTPS. Local file copies, synchronization metadata, logs, and OAuth credentials are stored on the owner's computer, under the owner's control.

This website does not receive or store Drive file contents, account credentials, or OAuth tokens. The sync application does not send this data to the website's GitHub repository or GitHub Pages hosting.

The application does not sell Google user data or disclose it to advertisers or analytics providers. Google's handling of Drive data is governed by Google's own privacy policies. Security of local copies and local credentials depends on the owner's computer and its access controls.

Retention and deletion

Local file copies, metadata, logs, and credentials remain until the owner removes them or the configured synchronization changes them. Two-way sync can propagate deletions. The configuration does not create separate recovery copies of overwritten user files; Google may independently retain trash or version history under its policies.

The owner can revoke authorization in Google Account third-party connections and remove stored credentials from the local rclone configuration. Revocation stops future authenticated access but does not automatically delete copies already downloaded. The owner must separately remove unwanted local copies.

Website hosting

These are static pages hosted on GitHub Pages. They contain no analytics scripts, advertising, or contact forms. GitHub may process ordinary web-request information under the GitHub Privacy Statement.

Contact and changes

Questions about this application or policy may be raised through the maintainer's GitHub issues page. Do not post passwords, tokens, or private files there.

Updates to this policy will be published on this page with a revised effective date.
